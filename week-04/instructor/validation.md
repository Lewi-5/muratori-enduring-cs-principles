## Mutation check of the harness

Each mutation was applied to a copy of the reference source, the seven drivers were rebuilt and `tests/check.py` (GCC `-O0`) was run; the unmutated copy passed first, because a failing baseline would make every mutant look killed. The mutation script is not part of the package (it is a one-off harness that copies `instructor/src` and applies one textual replacement); the table below is its result. **90 mutants: 82 killed, 8 survived, and every survivor is an equivalent mutant or unreachable code**, not a test gap:

| Survivor | Why it is equivalent or unreachable |
| --- | --- |
| E03 `fputs` result of the rows unchecked; final `ferror` unchecked; header `fputs` unchecked | Each check alone is enough to notice a failure, since a failed write sets the stream's error indicator that `ferror` reports (and the fmemopen stream, which fails partway through the rows, is caught by the remaining checks). Removing all row checks together is killed (`no write checks at all`). |
| E03 header write unchecked *and* the loop checks kept | Same redundancy: a read-only stream still fails at the `ferror` at the end. |
| E04 `n > 20` identifier length check removed | A 21-digit number with no leading zero always exceeds `UINT64_MAX`, so the overflow guard rejects it. The length check is an early exit. |
| E05 `SIZE_MAX / sizeof(GeoPoint)` byte-count check removed | Unreachable on a 64-bit target with the course cap: no file can drive the capacity that high. It is a contract for a raised cap or a 32-bit `size_t`, argued by inspection. |
| E06 validating only the first point | The haversine validates every point again before `*out` is written, so a bad later point is still rejected with the output unchanged. |
| E07 grid index converted through `float` | Every index up to 2²⁴ is exactly representable as a `float`; the mutant is equivalent on the whole accepted domain (which is why the limit is 2²⁴). |

Killed mutants (82) cover, among others: E01 (no rejection sampling, threshold plus one, `<=`, low bits, wrong multiplier, output before advance, bound 0 accepted); E02 (sign lost, no zero padding, limit off by one, size off by one, any limit accepted, record limit swapped, partial write on failure); E03 (draws in the wrong order, `fclose` unchecked, no `remove` on failure, `remove` after a failed `fopen`, cap `>=`, identifiers from 0, `fflush` unchecked, cap missing in `write_csv_file`, no write checks); E04 (leading zeros, `-0.000000`, product-only overflow check, latitude limit 91 or three digits, `commas < 2`, `micro * 1e-6`, writes before validation, longitude limit 181, range reported as grammar, five fraction digits, upper digit check missing, sign not applied, empty line falling through); E05 (leak on `realloc` failure, `char` instead of `int`, line limits 126 and 128, NUL ignored, off-by-one at the cap, unclamped doubling and first allocation, wrong line numbers, count written early, rows not freed, `fclose` or `ferror` ignored, final line dropped, blank line skipped, header unchecked or prefix-only, error not reported on success); E06 (exclusive boundary, minimum initialized to zero, radius limit, sum in `float`, sum or maximum over the wrong points, output written before validation, center not validated, negative or NaN radius accepted, wrong radian factor, `points` counting `within`); E07 (compensation without the branch, dropped correction, pairwise block 16 or 100,000, linear split, explicit grid that accumulates, validation after writing, limit `>=` in each grid function, empty sum rejected, missing final-element check, non-finite step accepted, NULL accepted). Four of the tests exist because mutation testing first found a survivor: the exact-threshold states for `lcg_below`, the injected `fflush` failure, the reordered `cancel` inputs, and validation of an empty dataset or an `n == 0` grid.

## Limits

One machine, one glibc, two compilers. The tolerances and recorded errors are this platform's; a different libm may differ in last digits and should still pass every assertion, which is why nothing is compared bit-for-bit. Claims resting on Annex F, the x86-64 ABI, `EISDIR` on a directory `fopen`, or `fmemopen` are gated or labelled as platform observations; the forced-skip builds test the gating path, not another platform. The locale-dependent decimal point could not be reproduced because the `de_DE` locale is not installed on the reference machine. No claim is made that the spherical model agrees with a real geodesic. Sanitizer flags (`-fno-pie`, `-no-pie`) are tooling choices for this Linux configuration, not C rules.
